# ADR 0018: 画像 PDF の変換は OCRmyPDF → Docling を土台にし、問題ページだけ LLM で照合する

- Status: Accepted（「問題ページだけ LLM で照合する」と「再処理の単位は決めない」は [0019](0019-image-pdf-reconcile-scope-and-assembly.md) で Superseded）
- Date: 2026-09-24
- Supersedes: [0017](0017-image-pdf-conversion-keeps-only-page-structure.md) の「再処理の単位はページ」

## Context

[0017](0017-image-pdf-conversion-keeps-only-page-structure.md) は途中の経路を固定せず、検証で決めるとしていた。
3 つの資料で検証した。

- 評論本（KFX から書き出した PDF。組版は密な囲み枠とスコア表が中心）
- ルールブックの見開きスキャン 2 冊（A3 横、400dpi、カラー）

分かったこと:

- **原ページだけを LLM に渡す経路は読めない。**
  - OpenAI の PDF 入力はページを低解像度の画像にする。1 ページの入力が 404 トークンで、モデル自身が「解像度が低く判読できない」と返した
  - 画像を `detail: high` で直接渡しても、短辺 768px に縮められて小さい文字が潰れる。読めない箇所に原ページに無い名前を書いた
- **OCRmyPDF の `--deskew` は、Docling のレイアウト判定を壊すことがある。**
  - 評論本では、`--deskew` がページ画像を描き直した結果、Docling が 16 ページ中 13 ページで全面を 1 枚の図と判定し、本文が Markdown から消えた
  - `--oversample` / `--rotate-pages` では起きない。スキャンのルールブックでは `--deskew` でも起きなかった
- **Docling 自身の OCR は、OCRmyPDF より文字の質が明らかに悪い。**
  - 領域ごとに OCR するので囲み枠をまたいで行が混ざる問題は消えるが、3 資料とも 1 文字ごとの空白と英字の羅列が出た
- **OCRmyPDF → Docling の本文は、普通の組版ならかなり読める。** 崩れるのは次の箇所で、資料ごとに癖が違う
  - 密に並んだ囲み枠（行が枠をまたいでつながる）
  - 色の付いた帯の上の小さい文字（英字の羅列に化ける）
  - 図と判定された領域の中の文字（JSON には残るが Markdown に出ない）
  - 見開きスキャンの読み順（左右のページをまたいで並ぶ）

## Decision

### 経路

```text
原本 PDF → OCRmyPDF → Docling → 問題ページの検出 → 問題ページだけ LLM で照合 → 組み立て
```

- OCRmyPDF は `--deskew` を使わない。原本がスキャンでも付けない（付けて得られる改善より、Docling が本文を落とす害が大きい）
- Docling は standard パイプラインを `--no-ocr` で使い、OCRmyPDF のテキスト層を読ませる。Docling 自身の OCR は使わない
- 問題ページの検出は、Docling の JSON から機械的に行う（図の中の文字の割合、英字の割合、文字数）
- LLM には原ページの画像を直接渡す（PDF では渡さない）。候補として OCR と Docling のテキストを添え、食い違ったら画像で決めさせる

### LLM は固定しない

照合に使う LLM は差し替えられるようにする。候補は Claude と OpenAI。
どちらも「指示・画像・本文を受けて応答の本文を返す」同じ呼び方の部品にする。

### 再処理の単位は決めない

0017 の「ページごとの変換結果があればそのページは変換し直さない」を置き換える。
変換の大半は OCRmyPDF と Docling で、ページ単位の LLM 課金が前提ではなくなった。
ページ単位の生成物を作ってもよいが、それを再処理の単位として保証しない。

## Consequences

- 本文の誤読は tesseract の精度で決まる。LLM で照合しないページには OCR の誤りがそのまま残る
- 囲み枠が密な資料や色帯の多い資料では、ほぼ全ページが問題ページになり、LLM の費用が資料の大半にかかる
- 見開きスキャンは読み順が崩れるので、左右に分割する段を OCR の前に足す必要がある
- 問題ページの検出の閾値は 3 資料だけから決めた。資料が増えたら見直す
- LLM が画像を縮めて扱うので、細かい文字のページは照合でも読めないことがある。領域を切り出して渡す工夫が要るかもしれない
