# ADR 0019: 照合するページは資料ごとに選び、Docling の Markdown をページ単位で差し替えて組み立てる

- Status: Accepted
- Date: 2026-09-24
- Supersedes: [0018](0018-image-pdf-pipeline-ocrmypdf-docling-then-llm.md) の「問題ページだけ LLM で照合する」と「再処理の単位は決めない」

## Context

[0018](0018-image-pdf-pipeline-ocrmypdf-docling-then-llm.md) の経路を部品にし、見開きスキャンのルールブック 2 冊
（14 ページ / 18 ページ。見開きを分けた後）で最初から最後まで流した。

分かったこと:

- **問題ページの検出に掛からないページにも、OCR の誤読がそのまま残る。**
  - 語の途中の空白、誤読（「通真」「上げばる」）、意味のない英字列、数字周りの誤読が、英字の割合 5% 前後のページに出る
  - 英字の割合が閾値をわずかに下回った、ほぼ文字化けのページが照合から漏れた
  - アイコン付きの段落を Docling が落としたページは、字が崩れていないので検出の条件に掛からない
- **照合したページは読める本文になる。** 読み順・見出しが戻り、誤読が直り、図の中の得点表が表として復元された
- **照合の費用は小さい。** Claude で 1 ページ 入力 7〜10k / 出力 1.5〜4k トークン、20 秒前後
- **Docling の CLI はページ単位の Markdown を出せない。** 文書全体で 1 つの Markdown になる。docling-core の API はページを指定して書き出せる
- **見開きは、画像を描き直さずにページの表示範囲だけを左右に切れば、OCRmyPDF / Docling をそのまま通る。**
  左右それぞれのページの文字だけが拾われ、見開きのままでは問題ページだった片側が問題なしになった

## Decision

### 照合するページは資料ごとに選ぶ

- ルールブックのように数十ページの資料は、全ページを照合する
- 数百ページの本は、問題ページの検出で照合するページを絞る
- どちらにするかは変換のたびに人が選ぶ。LLM を呼ぶ前に、照合するページ数を示して了承を取る

### 組み立て

- Docling の JSON を、各ページの先頭にマーカーを置いた Markdown に書き出す
- 照合したページは、その Markdown の同じページを差し替える。照合しないページは Docling の本文のまま
- 照合はページ単位でやり直せる（出力の無いページだけ照合し直す）

### 見開き

- OCR の前に、全ページを左右 2 ページに分ける。画像は描き直さず、表示範囲だけを切る
- マーカーのページ番号は分けた後の番号にする

## Consequences

- 全ページを照合する資料では、問題ページの検出は使わない
- 照合しないページの本文は OCR の精度のままなので、数百ページの本では誤読が残る
- 見開きでないページ（表紙だけ単ページなど）が混ざる PDF、右から左に読む本は、分割の段が扱えない
- マーカーのページ番号が原本の PDF のページ番号と一致しなくなる資料がある（見開きを分けたとき）
