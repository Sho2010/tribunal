# 画像 PDF の Markdown 化

テキストを持たない PDF（スキャン / 画像のみ）を、ページ番号を保った Markdown に変換する。
Rule / Strategy のどちらの資料にも使う。

変換に LLM を使うため、**本文は再実行で変わりうる。** ここで保証するのは入出力の場所・名前と、
出力 Markdown の構造だけ。途中の経路（OCR / レイアウト解析を挟むか、ページ画像を直接渡すか）は
保証の対象外で、検証の結果で入れ替えてよい。

## 入出力

```text
<input>.pdf                           # 入力。変更しない
<work_dir>/                           # 作業ディレクトリ。生成物はすべてここに出す
  pages/page-0001.md                  #   ページ単位の変換結果（1 始まり、4 桁）
  document.md                         #   最終出力
```

- 入力 PDF と作業ディレクトリは**両方とも引数で渡す。** パスから game_id や名前を導出しない
- 作業ディレクトリの外に書かない
- 作業ディレクトリは `temp/` の下に置く。`temp/` は `.gitignore` で丸ごと落ちるが、それ以外の場所は push されうる
  （中間生成物も著作物の派生物）
- `pages/` 以外の中間生成物（OCR 結果、ページ画像など）の名前と構成は保証しない
- 最終出力を `games/<game_id>/{rule,strategy}/` へ置くのも、Vector Store へ載せるのも手動

## 入力の検査

- **テキスト層を持つ PDF（フォントが埋め込まれている）は変換せずに止まる。**
  born-digital PDF を画像として読み直すと、正しい既存テキストより悪い結果になる
- ページ範囲を指定して一部だけ変換できる。このとき `document.md` は作らない

## ページ単位の変換結果

`pages/page-NNNN.md` は次を満たすときだけ保存する。満たさなければ保存せず、そのページは失敗として扱う。

- 先頭が `<!-- source_pdf_page: N -->` で、N がファイル名の番号と一致する
- 全体がコードフェンスや JSON で包まれていない

失敗したページがあっても他のページの変換は続ける。

## 出力 Markdown

`document.md` は `pages/` を番号順に連結したもの。

- 各ページの先頭に `<!-- source_pdf_page: N -->` を置く
- N は PDF のページ番号（1 始まり）。**1 から総ページ数まで、欠番・重複なしで昇順に並ぶ**
- 書籍に印刷されたページ番号とは別物として扱い、N に混ぜない
- 白紙ページもマーカーは出す（本文は空でよい）
- 判読できない箇所は推測で埋めず `[判読不能]` と書く
- 原ページに無い内容（要約、解説、補足）を足さない
- front matter は付けない。処理の来歴（使ったツールや prompt の版）も出力に書かない

**全ページの `pages/page-NNNN.md` が揃うまで `document.md` を作らない**（既にあれば更新しない）。
欠けているページ番号を報告して終わる。欠けた最終出力を Vector Store に載せる事故を防ぐ。

## 再実行

- `pages/page-NNNN.md` が既にあるページは変換し直さない。失敗したページだけが再実行の対象になる
- やり直すときは、該当ページのファイルを消して再実行する
- `document.md` は毎回 `pages/` から組み立て直す。組み立てで本文を書き換えない

## Vector Store への登録

手動で行う。登録するのは最終出力の `document.md` だけで、中間生成物や OCR 済み PDF は載せない。

- 登録時に file attribute `game_id` を付ける。付けないと、`game_id` で絞り込んだ検索から外れる
- 登録したファイル名が Slack の回答に出典として表示される。`document.md` のまま載せず、資料名を付ける
- Rule 資料は Rule Store、Strategy 資料は Strategy Store に載せる。片方にまとめない

## 受け入れ条件

```text
N ページの画像 PDF を変換する
 → document.md に source_pdf_page マーカーが 1..N の順で N 個ある
 → 作業ディレクトリの外にファイルが増えていない
```

```text
テキスト層を持つ PDF を渡す
 → 変換せずに止まる
```

```text
ページ範囲を指定して変換する
 → 指定したページの pages/page-NNNN.md だけができる
 → document.md はできない
```

```text
一部のページが失敗する
 → 成功したページの pages/page-NNNN.md は残る
 → document.md は作られず、失敗したページ番号が報告される
 → 再実行すると、失敗したページだけが変換される
```

```text
1 ページ分の pages/page-NNNN.md を消して再実行する
 → そのページだけ変換し直され、document.md に反映される
```

## 保証していないこと

- 本文の正確さ。数字、カード名、表の読み取りは誤りうる。原ページとの照合は人が行う
- 同じ入力から同じ本文が出ること
- EPUB など PDF 以外の入力

## 関連

決定の理由: `tribunal-decisions` の「画像 PDF の変換はページ構造だけを保証し、中間生成物を temp に閉じる」
