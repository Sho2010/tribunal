# 画像 PDF の Markdown 化

テキストを持たない PDF（スキャン / 画像のみ）を、ページ番号を保った 1 つの Markdown に変換する。
Rule / Strategy のどちらの資料にも使う。

保証するのは入力の扱いと最終出力の構造だけ。途中の経路・中間生成物・再実行の単位は保証しない。
本文は LLM / OCR を通すので、再実行で変わりうる。

## 入力

- 原本の画像 PDF。変更しない
- **テキスト層を持つ PDF（フォントが埋め込まれている）は変換せずに止まる**

## 最終出力

1 つの Markdown ファイル。

- 各ページの先頭に `<!-- source_pdf_page: N -->` を置く
- N は PDF のページ番号（1 始まり）。**1 から総ページ数まで、欠番・重複なしで昇順に並ぶ**。揃わないものは最終出力として出さない
- 書籍に印刷されたページ番号は N に混ぜない
- 白紙ページもマーカーは出す
- 判読できない箇所は推測で埋めず `[判読不能]` と書く
- 原ページに無い内容（要約、解説、補足）を足さない
- front matter も処理の来歴（ツール、prompt の版、model）も書かない

## 置き場所

- 中間生成物も最終出力も `temp/` の下に置く。それ以外の場所は push されうる（著作物の派生物）
- 1 回の実行の生成物は 1 つのディレクトリにまとめる。ディレクトリは実行時に指定し、名前の付け方は決めない
- ツールが終了時に自分で消す一時ファイルは、この限りでない
- 最終出力を `games/<game_id>/{rule,strategy}/` へ置くのも、Vector Store へ載せるのも手動

## 部品

- パイプラインは部品（スクリプト）の組み合わせで作る。1 つの部品は 1 つの変換だけをする
- 部品の入出力は、引数で渡すパスか標準入出力で受け渡す。他の部品の出力の置き場所や、作業ディレクトリの構成を前提にしない
- 結果は stdout（または出力パス）に出し、進捗やエラーは stderr に出す

## 保証していないこと

- 本文の正確さ（数字、カード名、表）。原ページとの照合は人が行う
- 同じ入力から同じ本文が出ること
- PDF 以外の入力

## 関連

決定の理由: `tribunal-decisions` の「画像 PDF の変換はページ構造だけを保証し、中間生成物を temp に閉じる」
