# intent routing

質問を Rule と Strategy のどちらとして扱うかを決める。

## 要件

- 行頭の明示タグがあれば、それに従う
  - Strategy: `戦略:` / `strategy:` / `[戦略]` / `[strategy]`
  - Rule: `ルール:` / `rule:` / `[ルール]` / `[rule]`
  - 全角コロン（`：`）も受ける。大文字小文字は区別しない
  - **行頭のみ**。文中に現れた同じ文字列はタグとして扱わない
- **タグは質問文から除去してから検索に渡す**
- タグが無ければ推測する。推測が決められない場合は **Rule として扱う**
- **タグなしで処理した場合、どちらとして扱ったかを回答に添える。** タグありのときは添えない

## 受け入れ条件

```text
「ルール: ドラフトの定石は?」を投げる
 → Rule として処理される（戦略寄りの語を含んでいても、タグが優先される）
 → 検索には「ドラフトの定石は?」が渡る（タグは除去される）
 → 回答に振り分けの注記は付かない
```

```text
「この戦略: について教えて」を投げる
 → 行頭ではないのでタグとして扱わない（質問文からも除去されない）
 → タグなし扱いなので keyword で推測され、振り分けの注記が付く
```

```text
どちらとも判断できない質問をタグなしで投げる
 → Rule として処理される
 → 回答の末尾に、ルールとして答えた旨と、戦略なら「戦略:」を付けるよう促す注記が付く
```

## なぜ曖昧なら Rule か

外したときの被害が非対称。

```text
strategy 質問を rule で答える → 「資料に記載がありません」と返る（無害）
rule 質問を strategy で答える → 非公式資料でルールを語る（境界違反）
```

## 保証していないこと

- 判定の精度。keyword は当て推量の初期セットで、実際の質問を見て調整する前提。
  **確実に振り分けたいならタグを付ける**
- `hybrid`（ルールと戦略に跨る質問を両方の Store で扱う）は無い。Rule として処理される
- 聞き返しはしない
